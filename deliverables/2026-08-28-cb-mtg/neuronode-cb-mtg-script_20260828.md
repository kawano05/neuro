## 3. アプリ概要（0:12–0:28）

### 3-1. 設計思想 — 3つだけ覚えて帰ってもらう

> 「設計の柱は3つです。」

1. **課題中は画面全体がひとつのスイッチ**
   > 「課題が始まると、画面のどこを押しても、どの筋肉で押しても『押した』として伝わります。ボタンを狙う負担をなくし、『1回の入力』そのものに集中してもらうためです。」
2. **利用者の画面と支援者の画面を分離**
   > 「利用者にはゲームだけが見え、設定・記録・研究用の画面は支援者側に分けています。利用者の走査による誤操作を防ぐためです。」
3. **押したタイミングのずれを毎回記録**
   > 「早い・遅い・ばらつきを数字で残すので、同じ条件で訓練の前後や設定の違いを比べられます。記録は評価の材料であって、診断結果ではありません。」

技術的な補足（聞かれたら／エンジニアが同席なら）:

- 入力時刻はゲーム側でなくシェル（入力ファネル）が `performance.now()` で確定。全課題が同じ入口を通るので、課題間で測定条件が揃う
- iPadのSwitch Controlとアプリ内走査の**二重走査を構造的に防ぐ**切替手順を用意（アプリ走査OFF → iPad側ON → アプリのSwitch ControlモードON）

### 3-2. 課題（あそび）一覧 — 段階を踏んで「選ぶ・伝える」まで

> 「課題は反応確認から始めて、段階的に難しくなります。」

| 段階 | 課題 | 内容 |
|---|---|---|
| L0 反応確認 | いろと おと | 押すと色と音が変わる。入力の導通確認 |
| L1 視覚タイミング | リールを止める（ひとつ） | 1本のリールで目標図形を中央に止める |
| L2 逐次入力 | リールを止める（3つ） | 1入力1本、左から右へ順に止める |
| 反応抑制 | 高い音だけ / さかなつり | Go/No-Go課題。高音だけ押す・偽アタリを見送る |
| 応用 | アームを止める | 横→奥の順で位置を決める（走査選択の練習） |
| 教材 | まなぶ・つたえる | マッチング・VOCA・文字学習 |

**必ず添える一言**（先方が気にする可能性が高い）:

> 「リール課題は見た目はスロットですが、利用者の画面では『スロット』『BET』などの賭博表現は一切使いません。研究上も、視覚刺激への停止タイミングを測る測定課題として設計しており、成功・失敗を乱数や『惜しい』演出で操作することはありません。」

### 3-3. 記録の考え方

- 「そくてい」（固定条件・比較用）と「れんしゅう」（支援者が調整可）の2モード。どちらも条件をすべてセッションに記録
- 停止1回ごとに符号付きのずれ・絶対ずれなどをCSVへ出力（早押しは負、遅押しは正）
- **データはすべて端末内（localStorage）のみ。外部送信は既定で一切なし。** CSVは支援者が明示的に書き出したときだけ端末の外に出る

## 4. 実機デモ（0:28–0:45）

> 「ここからは実際に動くものをご覧ください。本日は実機を持参しておらず、ブラウザ版でのご説明になりますが、iOS版は同じコードからCapacitorで生成しており、iPhoneとNeuroNode実機での動作チェックは7月に完了しています。ブラウザでは、スペースキーやクリックがNeuroNodeの『1回の入力』に相当します。」

段取り（この順で。1画面ごとに一言添える）:

1. **スタート画面** — 「最初の1押しで音の準備と入力の導通確認を兼ねています」
2. **ホーム（アプリ選択）** — 「項目が順番に光り、スイッチ1つで選べます」→ 走査を数周見せてから決定
3. **リールを止める（ひとつ）= L1** — 「ここからは画面全体がスイッチです」→ 2〜3回停止して見せる → **先方に交代して体験してもらう**（約2分。「スペースキーを1回押すだけです」とキーボードかマウスを渡す）
4. **リザルト画面** — 「命中率と、ずれの中央値・方向を穏やかに表示します。利用者向けなので責める表示はしません」
5. **リールを止める（3つ）= L2** — 「左から右へ、1入力で1本ずつ。逐次入力の練習です」
6. （時間があれば）**さかなつり or 高い音だけ** — 「見送る練習、Go/No-Goです」
7. **支援者ビューへ切替** — 設定タブ、研究者モードトグル、そくてい/れんしゅうの切替を見せる
8. **CSV出力** — サンプルを見せ、「この形式で訓練前後の比較ができます」

デモ中の注意（読み上げない）:

- 体験してもらうときは **L1（ひとつ止める）** に限定。初見で成功体験が得やすい
- 「実機では？」と聞かれたら: 入力経路（NeuroNode→Switch Control／タップ／キー）が違うだけで、課題の内容と記録は同一、と答える
- GitHub Pages側が不調ならローカル版（`localhost:5173`）へ即切替。その場で粘らない

## 想定Q&A

**Q. データはどこに保存されますか？個人情報は？**
> 「すべて端末内のlocalStorageのみで、外部送信は既定で一切ありません。CSVも支援者が明示的に書き出したときだけ端末の外に出ます。倫理面は粂野先生の指導のもと、『既定でデータを保存しない』方針として整理しています。」

**Q. スロットのような見た目は問題になりませんか？**
> 「利用者画面では賭博表現を使わず、『リールを止める』と表示しています。研究上は停止タイミングの測定課題で、乱数で成否を変えたり射幸心を煽る演出を入れたりはしていません。」

**Q. iPadのSwitch Controlとぶつかりませんか？**
> 「二重走査を防ぐ切替手順を設計に組み込んでいます。アプリ側の走査を止めてからiPad側をONにする順序で、利用者が唯一の操作手段を失わないようにしています。」

**Q. 実機（iPad・NeuroNode）でも同じように動くのですか？**
> 「はい。iOS版は同じコードからCapacitorで生成しており、iPhoneとNeuroNode実機での動作チェックを7月に完了しています。本日のブラウザ版とは入力の経路が違うだけで、課題の内容と記録は同一です。」

**Q. iOS版・リリースの状況は？**
> 「CapacitorでiOS化し、CIでビルド確認を通しています。実機での最終確認項目（Switch Control、アクセスガイド、NeuroNode実機）はiPadで実施します。リリース時期は研究のまとめと並行して詰めている段階です。」

**Q. 対象ユーザーは？**
> 「NeuroNodeを使いはじめる段階の方を、支援者と一緒に使う前提で想定しています。視覚課題が難しい方には、視覚課題を非表示にして聴覚課題だけを残す設定も用意しています。」

**Q. 効果はどう測るのですか？**
> 「主要な指標は反応時間系の課題で、リール課題は停止タイミングの絶対ずれ・方向・ばらつきを副次評価として記録します。固定条件の『そくてい』モードで訓練前後を同一条件で比較できます。」
