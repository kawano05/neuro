# neuro

`neuro` は、NeuroNode 利用開始時の導入訓練を支援する iPad 向けアプリの Web プロトタイプです。
中核は、動く図形を1回の入力で1本ずつ止める**単一スイッチ式の視覚タイミング・逐次停止課題**です。

## 目的

本プロジェクトでは、NeuroNode 利用者が支援者と一緒に入力操作へ慣れるための訓練アプリを開発します。Web版で素早く試作・検証し、Capacitor によって iOS アプリ化することを前提にしています。

`slot-l1` は1本、`slot-l2` は3本のリールを左から順に止めます。研究上はカジノゲームではなく、視覚刺激に対する停止タイミング、逐次入力の完遂、早押し・遅押しの方向と絶対ずれを記録する `taskType: slot` / `protocolVersion: slot-v1` の測定パラダイムです。

- 1入力と1停止の対応を理解・練習する
- 利用者ごとの視覚停止タイミングの絶対ずれ・方向・ばらつきを把握する
- L2で左から右への逐次入力とラウンド完遂を確認する
- 訓練前後や固定条件間を、記録済みプロトコルだけで比較できるようにする

利用者画面では「スロット」、通貨、BET、BAR、777、ジャックポット等の賭博表現を使わず、「リールを 止める」「ひとつ 止める」「3つ 止める」と表示します。図形は丸・魚・星・花・鳥・四角の6種で、成功・失敗を入力後の乱数や人為的な近接失敗で変更しません。

旧 `rhythm-l1` / `rhythm-l2` のコード、`taskType: sms` セッション、設定、CSVは履歴互換のため保持しますが、利用者ホームの導線には出しません。`gonogo` と `calibration` は別の聴覚課題として残り、聴覚用 baseline 補正をスロット判定へ流用しません。

設計の詳細は `basic-design.md`（基本設計）・`detailed-design.md`（詳細設計）、固定した置換仕様は `docs/slot-game-replacement-plan.md` を参照してください。

## 画面フロー

利用者の世界（スタート〜ゲーム）と支援者の世界（タブ）を分離しています。

```
[スタート画面] → (1押しで AudioContext アンロック + 入力導通確認)
      │
      ▼
[アプリ選択]   → ゲームタイルのグリッド。走査で巡回、スイッチで決定
      │
      ▼
[ゲーム実行]   → 走査を完全停止し、画面全体が単一のスイッチになる
      │           （NeuroNode等の Switch Control との二重走査を構造的に防ぐ）
      ▼
[リザルト]     → 達成率・平均オフセット・ばらつき等を表示 → アプリ選択へ戻る
```

支援者向けビュー（効果測定・評価ログ・研究・操作訓練・設定）は既存タブとして残っています。操作訓練・効果測定・研究タブは「設定」画面の「研究者モード」トグル（既定OFF）で表示を切り替えます。設定・記録・研究データの変更は、各支援者ビューで「支援者編集を開始」を押したセッション中だけ有効です。このロックは認証ではなく、利用者の自前走査による誤操作を防ぐためのものです。

## あそび（ゲームタイル）一覧

ホームには6項目が並び、リール停止／さかなつり／まなぶ・つたえる は二階層目でさらに選びます。スロット2課題は `src/lib/games/slot.js` の共通エンジンを使います。

| ホームの行 | 二階層目 | ゲームID | 訓練段階 | 内容 |
|---|---|---|---|---|
| いろと おと | — | `color-legacy` | L0 反応確認 | 5回の色・音変化を進行ドットで示す |
| リールを 止める | ひとつ 止める | `slot-l1` | L1 視覚タイミング | 1本のリールで目標図形を中央へ止める |
| リールを 止める | 3つ 止める | `slot-l2` | L2 逐次入力 | 3本を1入力1本、左から右へ順に止める |
| 高い音だけ | — | `gonogo` | 聴覚反応抑制 | 高音（Go）なら押し、低音（No-Go）は見送る |
| アームを 止める | — | `crane` | 視覚・走査選択 | 横→奥の順にアームを止め、床の位置を決める |
| さかなつり | アタリで 釣る / 魚だけ釣る | `fishing` / `fishing-gonogo` | 反応時間・抑制 | 本アタリへ反応し、偽アタリを見送る |
| まなぶ・つたえる | マッチング / VOCA / 文字学習 | — | 教材 | ゲーム契約には乗せない教材 |

`slot-l1`、`slot-l2`、`crane` は `visualRequired: true` です。`hideVisualTasks` をONにすると「リールを 止める」カテゴリーごと非表示になり、画面注視が難しい利用者には聴覚課題を残します。

`そくてい`（`calibration`）は利用者ホームには出さず、設定画面から支援者と一緒に実施します。基準オフセットの測定手順そのものなので、支援者の難易度設定を一切受け付けません。

いずれのゲームも入力時刻はゲーム側ではなくシェル（`src/lib/neuronodeApp.js` の入力ファネル）が `performance.now()` で確定し、契約経由でゲームへ渡します。全ゲームが同じ入口を通ることで、入力系遅延の測定条件が課題間で揃います。

## むずかしさ — 「そくてい」と「れんしゅう」

難易度はセッション目的の2モードです（`src/lib/difficultyMode.js`）。`measure` は `slot-v1` の比較可能性を守る固定値、`practice` は成立範囲を探る支援者調整値です。

| スロット条件 | そくてい（固定） | れんしゅう（既定／調整範囲） |
|---|---|---|
| 周期 `cycleMs` | 3200ms | 3200ms／2800〜6000ms |
| 許容幅 `toleranceMs` | ±220ms | ±220ms／60〜220ms |
| L1 | 1リール × 8ラウンド | 1リール × 8／3〜20ラウンド |
| L2 | 3リール × 4ラウンド | 3リール × 4／2〜12ラウンド |
| 1リールの上限 | 4周期 | 4周期 |
| seed | `slot-measure-01` | 毎回可変、値はセッションへ記録 |

測定モードでは設定つまみを無効化し、走査対象からも外します。練習モードで値を変えても、`difficultyMode`、周期、許容幅、回数、seedをセッションとCSVへ保存します。表示は両モードとも同じ停止線と6図形を使い、スロット判定へ `visualGuidance` や聴覚 `baselineOffsetMs` を適用しません。

### スロットの測定値

停止1回をCSVの1行とし、`roundIndex`、`reelIndex`、目標・停止図形、入力時刻、最近傍の目標通過時刻、符号付きずれ、絶対ずれ、観測周期数、判定を記録します。早押しは負、遅押しは正です。描画の `requestAnimationFrame` は見た目だけを更新し、判定はシェルがイベント入口で取得した `performance.now()` と固定した周期・初期位相から計算します。

利用者向け結果は命中率、絶対ずれ中央値、符号付き平均ずれ、タイムアウト、余分な入力、最後の図形を穏やかに示します。主に見る指標は絶対ずれ中央値で、入力後の乱数による成否変更や「惜しい」を作る近接失敗はありません。

### 記録と互換性

新規データは `neuronode-slot-YYYY-MM-DD.csv` へ独立出力します。旧リズムCSV、走査CSV、反応時間CSVは別ファイルのまま維持し、異なる単位を混ぜません。保存先は `neuronode-prototype-state-v4` です。初回読込時はv3をコピー移行し、旧キーと `taskType: sms` セッションを削除・変換しません。不正なスロット試行は個別に除外し、必要な停止位置が欠けたセッションは `finished: true` のままにしません。

## 走査（スイッチで選ぶ）まわりの約束

- **アプリが走査を担当するときは、現在位置がいつでも画面に見えている。** 固定ドックと粘着タブバーのぶんを `scroll-margin` で避けます。
- **iPadのSwitch Controlを使うときは、支援者が「アプリ自動走査OFF → iPad側Switch Control ON → アプリのiPad Switch ControlモードON」の順で切り替える。** 最後の切替で黄色い枠と走査ドックを消し、シェル項目の選択をiPad側だけへ委譲します。利用者が唯一の走査を先に失わないための順序です。
- 通常のアプリ走査へ戻すときは「アプリのモードOFF（自動走査は停止したまま）→ iPad側Switch Control OFF → アプリ自動走査ON」の順に戻し、黄色い枠だけが動くことを支援者が確認します。
- 同モードをONにした時点でアプリTTSはいったんOFFになります。OS読み上げとの比較が必要なときだけ支援者が明示的にONへ戻し、アプリ音声の音量つまみで調整します。
- **画面が短いときは一覧をページに分ける**（3項目＋「つぎの ページ」、最後のページから先頭へ循環）。走査で選ぶ相手はスクロールを止められないので、選ぶたびに画面が動くと「選ぶ」課題が「選ぶ＋動く画面を追う」課題に変わります。詰めるのは1ページあたりの項目数と飾りであって、タップ標的の大きさではありません。
- **タップ標的は44px以上**（Apple HIG / WCAG 2.5.5）。
- これらは目で見れば分かる一方、壊れてもビルドは通るので、`tests/web-smoke.mjs` が5つの実寸（デスクトップ・iOS相当の狭幅・iPad縦・スマホ縦・スマホ横）で毎回確かめます。iPad条件では507x1194のSplit View相当へ途中で縮めた確認も行います。

## 起動

Node.js 22 以上を推奨します。

```powershell
npm install
npm run serve
```

ブラウザで `http://localhost:5173` を開きます。

## テスト

```powershell
npm run check
npm test
```

`npm test` は `test:unit`（slot-v1の位相・境界・固定seed・逐次状態・v3→v4移行・CSV列・画像品質を含む単体テスト）と `test:web`（本番ビルド後のPlaywrightスモーク＋PWA更新競合テスト）を順に実行します。

`test:web` は5つの実寸で走ります。

| プロジェクト | 実寸 | 何を見るためか |
|---|---|---|
| `chromium-desktop` | 1280x900 | AudioContext が要る検査（音の契約） |
| `mobile-webkit-like` | 390x664 | iOS Safari に近い狭い画面 |
| `ipad-portrait` | 834x1194 | 主対象の端末 |
| `phone-tall` | 390x812 | 縦長スマホでの画面崩れ |
| `phone-landscape` | 844x390 | **幅ではなく高さが足りない**狭さ。ここは長らく検査の外にあり、モバイル用の圧縮が丸ごと効いていなかった |

確認しているのは、スタート→ホーム→ゲームの通し、生成した6図形PNGの実画面読込、L1の1停止と中断保存、L2の4ラウンド×3本の左→右停止、300ms入力ガード、長押しとclick-only支援入力、キーボード操作、自動走査停止、iPad Switch ControlモードとSplit View、PWA配信・オフライン再読込・更新競合です。

- 走査の現在位置が固定ドック/粘着タブバーの裏に回らないこと
- 全画面で横スクロール0・タップ標的44px以上・選択肢の名前が読める幅にあること
- リザルトに支援者用UIが出ないこと、文字入力中はドックが退避すること
- 効果音は設定で切れるが、**測定の合図音は切れない**こと（生成された AudioNode の種類を数えて見分ける）
- AudioContext が無い／停止中の端末では、聴覚課題（`gonogo`、`fishing`）が刺激なしのセッションを作らないこと。スロットは `performance.now()` の視覚課題として音なしでも成立すること
- 実行中にページ例外・`console.error` が出ていないこと

### 実機が使えないときの見かた

`scripts/capture-screens.mjs` が3つの実寸で主要画面を撮り、CI が成果物として上げます（`artifacts/screens`）。ビルドとテストが緑でも「画面がどう見えるか」は分からない——余白の破綻も文字の折り返しも、テストを通り抜けます。判定はしないので、失敗しても CI は落としません。

```powershell
node scripts/capture-screens.mjs artifacts/screens
```

## iOS化

Mac + Xcode 環境で以下を実行します。

```bash
npm install
npm run build
npm run cap:add:ios
npm run cap:sync
npm run cap:open:ios
```

`cap:add:ios` は CocoaPods 版の Xcode workspace を生成します。CI とローカル検証では `ios/App/App.xcworkspace` を `App` scheme でビルドします。

Windows上ではXcodeや本物のiOS Simulatorは使えないため、GitHub Actions の macOS runner で Capacitor iOS プロジェクト生成とXcodeビルド確認を行います。最終的な Switch Control、Guided Access、NeuroNode実機操作は iPad 実機で確認します（`basic-design.md` §10・`docs/testing-without-apple-devices.md` 参照）。

## 操作

- `Space` または `Enter`: シェル画面ではハイライト中の項目を選択／ゲーム中は画面全体への入力として扱う
- `ArrowRight`: 走査ハイライトを手動で次へ移動（シェル画面のみ）
- `Escape`: シェル画面では走査停止／ゲーム中はゲームを中断してホーム（またはアプリ選択）へ戻る
- 画面下部の「入力」ボタン: 単一スイッチ入力の代替（シェル画面）
- ゲーム画面は全画面が単一のスイッチ（タップ・クリック・Space/Enter）

## 実装メモ

- フロントエンド: Svelte + Vite
- 音: 残存する聴覚課題は Web Audio、スロットの停止・完了は控えめな合成効果音。判定そのものは音へ依存しない
- iOS化: Capacitor
- データ保存: localStorage（`neuronode-prototype-state-v4`）。新規の主データはスロット専用CSV、旧リズムデータとCSVは履歴互換として保持
- 画像: `src/assets/slot/slot-symbol-strip-v1.png`（生成画像）をガイドとして表示し、実際のリール図形はCSS形状・アイコンでも識別できるよう冗長化
- 公開: GitHub Pages
- オフライン: ビルド時にindex・ハッシュ付きWeb資産・manifest・iconを列挙し、Service Workerのinstall時に内容ハッシュ版の不変cacheへprecache。オンライン時はnetwork-firstで最新応答を返し、cacheは次版SWのinstall時に版単位で更新（Capacitorでは登録しない）
- CI: 単体・Web煙テストでPages公開をゲート + macOS上のCapacitor iOSビルド確認
