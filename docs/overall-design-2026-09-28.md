# 全体設計（2026-09-28）— 押したら、世界が応える

この文書は、利用者の世界（スタート・ホーム・遊び・けっか・学ぶ／伝える）の**全体設計**を
書き直したもの。打ち合わせの要望（`docs/design-renewal-2026-09-25.md` §1）を土台に、
5巡の改修で分かったことと、利用者側からの次の依頼を合わせて組み直した。

> 技術負債を返済することを恐れないでください。モーショングラフィッカーとして最高の作品を
> 出せるように。クライアントの話を含めたうえで全体設計をしなおしてください。
> ドーパミン、脳汁が出るような演出を追加してください。（利用者側、2026-09-28）

研究の設計（測定の手順・判定・記録）は `detailed-design.md` と `basic-design.md` のまま。
この文書はその上に乗る「体験の設計」を決める。

## 1. だれのための、何のアプリか

| 打ち合わせで言われたこと（§1） | 設計にどう効くか |
|---|---|
| 利用者は NeuroNode を使う重度の方。何をやっても「初めての経験」。認知面は幼い子どもを想定してよい（1.1） | 説明ではなく**起きたことで分かる**画面。絵と音と動きが主役、文字は脇役 |
| NeuroNode では「押した」感覚そのものが無い。何をしたら何が起きたのかが最初は分からない（1.4） | **押したら、必ず・すぐ・大きく返す**。返りが小さいと「押した」が伝わらない |
| 失敗がほぼ無く、やったことが全部プラスになる遊びを。自分でできた経験が少ない（1.4） | 失敗の演出は作らない。外れても「おしい！」と軽く、成功は**だんだん盛り上げる** |
| 音はとても大事。画面を見られない人にも届く。読み上げより効果音（1.7） | 演出は**音と一体**で設計する。絵だけ・音だけにしない |
| 強すぎる音ばかりだと発作を起こす人もいる。選べるように（1.7） | 光・音・動きに**安全の上限**を決め、強さを選べるようにする（§4） |
| できたときに笑い声や「やったー」で、周りが家族だけでも盛り上がる（1.7） | おいわいは**部屋ごと盛り上がる**大きさで。見ている家族にも届く |
| リールは当たったと分かる派手な演出を。間違えたときはへこませず、あっさり次へ（1.5） | 当たりは派手に、外れは短く。れんしゅうの回だけ |
| けっかは最小限。点数と「よくできました」「きみはプロだ」（1.6） | けっかは**星が飛び込んでくる**瞬間を主役に、数字は小さく |
| 目的は、市販のコミュニケーションアプリへ進むための最初の練習（1.1） | 「押す → 世界が応える」の手応えを覚えてもらうことが、すべての遊びの共通の目的 |
| 展示会（国際福祉機器展）でデモしたい | 通りがかった人の目を止める**見栄え**も要件 |

## 2. 体験の原則（5つ）

1. **押したら、必ず・すぐ・大きく返す。** 押してから 1 コマ（16ms）以内に画面が動き始め、
   音が鳴る。返りは「押したもの」に起きる（押した場所から波が広がる、押したものが弾む）。
2. **だんだん盛り上がる。** 1回目より2回目、2回目より3回目。粒の数・高さ・色・音の高さを
   少しずつ上げ、5回目で最高潮に。先が楽しみになる流れが「もう1回」を生む。
3. **やったことが全部プラス。** 外れの演出は作らない。外れたときは短く「おしい！」と言って
   次へ。できたことを数えて見せる（点・星・並べた絵）。
4. **びっくりさせすぎない。** 光の点滅・音の大きさ・揺れには上限がある（§4）。驚かせるのは
   大きさではなく**音色と形**。強さは支援者が選べる。
5. **そくていの回は変えない。** 測定の手順（合図・目標・判定・見え方）は `MEASUREMENT_PROTOCOL`
   のまま。演出を足すのは、はじめの遊び・ボールを打つ遊び・れんしゅうの回・けっか・ホームだけ。

## 3. ごほうびの文法

どの遊びも、同じ文法で返す。遊びごとに違うのは「何が起きるか」の絵柄だけ。

```
押す ─▶ ① 手応え（0〜120ms） ─▶ ② 起きたこと（〜400ms） ─▶ ③ 進みぐあい（〜800ms） ─▶ ④ 休み
                                                                  │ 5回目
                                                                  ▼
                                                           ⑤ フィナーレ（〜2.5s） ─▶ けっか: ⑥ 星が飛び込む
```

| 段 | 絵 | 音 | 決まり |
|---|---|---|---|
| ① 手応え | 押したものがつぶれて弾む（squash & stretch）。押した場所から輪が広がる | 押したときの音（遊びの設定で選んだもの） | 入力から 1 コマ以内に始める。ここだけは「なし」でも消さない |
| ② 起きたこと | ポンと出る・割れる・色がつく・打球が飛ぶ。粒（きらきら・紙吹雪・しぶき）がはじける | 起きたことの音（割れる・塗る・カキーン） | 粒の数と速さは、回を追うごとに上がる（§3.1） |
| ③ 進みぐあい | 進みの点がひとつ、弾んで埋まる。埋まった点が光る | 小さな「ポン」（点が埋まる音） | 残りは声で（「あと 3こ」）。声は効果音が終わってから |
| ④ 休み | 画面は落ち着く（常に動くものを置かない） | 無音 | 次の入力を待つ。待たせる演出はしない |
| ⑤ フィナーレ | 紙吹雪の雨・花火・星の大きな輪。主役の絵がジャンプする | ファンファーレ → 歓声と拍手 → 笑い声 → 「やったー」の声 | 声は効果音のあと（重ねると声に埋もれる。§3.17 の測定） |
| ⑥ 星が飛び込む | けっかの星が1つずつ飛び込んで弾む。一言がハンコのように押される。数字が数え上がる | 星ごとに上がっていく音 | 3つとも同じ速さで、最後の星がいちばん大きく |

### 3.1 だんだん盛り上がる（エスカレーション）

回の番号 k（0〜4）で、強さの係数 `e = 1 + 0.35k` を掛ける（5回目は 2.4 倍）。

- 粒の数 × e、はじける速さ × √e、粒の色の数を k で増やす（1回目は1色、5回目は虹）
- 押したときの音の高さ: 楽器の音はペンタトニックで上がる（ドレミソラ）。明るい効果音は
  回ごとに半音2つずつ上げる。**大きさは上げない**（§4）
- 進みの点は、埋まるたびに少しずつ明るく・大きく弾む

### 3.2 ヒットストップとカメラ

- **ヒットストップ**（当たった瞬間に 60〜90ms だけ止める）: ホームラン、リールの「ぴったり」
  （れんしゅう）。止めることで「当たった」が体に届く。計時には触れない（判定は入力の時刻で
  済んでいる。止めるのは見た目だけ）
- **カメラの寄り**（舞台全体が 1.03 倍に寄って戻る、180ms）: フィナーレ、ホームラン
- **画面の揺れ**: ホームランとフィナーレだけ、6px・300ms まで。強さ「ひかえめ」（すっきり）
  以下では揺らさない

## 4. 安全の決まり（光・音・動き）

打ち合わせで「強すぎる音ばかりだと発作を起こす人もいる」と言われた（1.7）。光も同じ扱いにする。
エンジン（`src/lib/fx/`）が守るので、遊びの側で破ることはできない。

| 対象 | 上限 | 根拠 |
|---|---|---|
| 明るさの点滅 | 画面全体・広い面を明滅させない。明るい光（グロー）は 1秒に3回まで、1回は 250ms 以上かけて消える | WCAG 2.3.1（3回の点滅）。光感受性発作の目安 |
| 赤の点滅 | 飽和した赤で点滅させない（粒の色に赤は使うが、面では光らせない） | 赤の点滅の基準 |
| 揺れ | 6px・300ms まで。連続して揺らさない | 酔い・前庭の不快 |
| 粒の数 | 同時に 320 個まで（端末の重さの上限も兼ねる） | 画面が埋まって何が起きたか分からなくならないように |
| 音 | 大きさは既定の上限の中（`audio.js`）。盛り上げは高さと音色で | §3.17 の測定 |

**演出の強さ**（支援者の設定「見え方・音」）: なし／ひかえめ／ふつう（既定）／はで。

- なし … ① 手応えと ② 起きたことの絵は残す（押した結果が分からなくなるので消さない）。粒・揺れ・
  フィナーレの紙吹雪は出さない
- ひかえめ … 粒 0.4 倍、揺れなし、フィナーレは小さな星の輪だけ
- ふつう … 上の表のとおり
- はで … 粒 1.5 倍、フィナーレに花火を足す（展示会向け）。上限（§4 の表）は同じ
- 端末の「視差効果を減らす／動きを減らす」（prefers-reduced-motion）は見ない（2026-10-01、ユーザーの
  判断。はじめは「ひかえめ」より強くしない決まりだった）。強さは支援者の設定だけで決める

## 5. 測定との境界

- **そくていの回**（`difficultyMode: "measure"`）: 何も足さない。演出エンジンは呼ばれても
  何もしない（`fx.forMeasurement()`）。
- **れんしゅうの回**（タイミングの遊び4つ）: 当たり・つかんだ・釣れた、に演出を足す。
  演出の強さは測定の条件になりうるので、`session.config.fxLevel` に残す（sanitize → CSV まで。
  リポジトリの決まり「測定条件は禁止せず記録する」）。
- 演出は**入力より後**にだけ起きる。合図より前に動くもの・音を置かない（予告になるため）。
- 演出の描画は入力の計時に触れない（入力の時刻はシェルの入口で取っている。§3.3 detailed-design）。
  重い処理をしないよう、粒は1枚のキャンバスに描き、動くものが無いときは止める。

## 6. 技術の設計

```
src/lib/fx/
  fxSafety.js    … 強さの段階・係数、明るい光の回数制限、揺れと光の上限（純粋関数、tests/fx.test.mjs）
  fxParticles.js … 粒の物理（重力・空気抵抗・回転・ひらひら）と形（星・きらきら・紙吹雪・しぶき・火花・輪・光、
                   遊びの形として紙テープ・ふうせん・ボール・魚・絵の具・音符）（純粋関数、tests/fx.test.mjs）
  fxEngine.js    … 画面いっぱいのキャンバス1枚（#fxLayer）。粒を描く。動くものが無ければ
                   requestAnimationFrame を止める。画素の密度は 1.5 まで、光は作り置きの絵
  fxMotion.js    … DOM の動き（つぶれて弾む・ポン・びくっ・揺れ・寄り・ハンコ・飛び込み・跳ねる）。
                   Web Animations API で個別の変形プロパティ（scale / rotate / translate）を動かす
  fxPresets.js   … 名前つきの演出（pressRing, popAppear, balloonPop, paintSplash, batHit, homerunSky,
                   trail, reelHit, craneGrip, craneWin, fishCatch, noteHit, finale, revealResult）。
                   §3 の文法とエスカレーションはここ
  index.js       … まとめ役（createFxSystem）。強さ＝設定「遊びの雰囲気」・そくていの回
src/lib/atmosphere.js … 遊びの雰囲気（なし・すっきり・にぎやか・おおさわぎ）の中身の表（ただ1つ。
                        2026-10-01〜）。fxSafety の係数・舞台・ホスト・けっかは、段の名前で分岐せず表を読む
                        （docs/rules/atmosphere.md）
src/lib/partyThemes.js … 遊びごとのお祝いの型（粒の形と色・びんの中身・観客・行進・見せ場・札。2026-10-01〜）。
                        段の表が「どれだけ」、この表が「何を」。絵は art/partyThemeArt.js
src/lib/presentation.js … 演出だけを閉じ込める境目。演出の例外で遊びと記録を止めない
src/lib/games/partyStage.js … ラッコ・キラキラびん・おいわいの舞台（ホストが遊びごとに1つだけ作る）。
                        見せ場（くす玉・額縁・応援団・行進）は遊びごとの型から
src/lib/games/beginnerKit.js
  createBeginnerFlow … はじめの遊びの流れ（押す → 音 → 進み → 5回目 → フィナーレ → けっか）と、
                       ファンファーレ・おいわいの時刻表。3つの遊びは「押したら何が起きるか」だけを書く
```

- 遊びの側は `ctx.fx` だけを見る（gameHost が渡す）。エンジンの中身を知らない。
- 動きの時間と曲線は、CSS の変数（`--motion-*`）と JS の定数（`fxMotion.js` の `MOTION`）で同じ値を持つ。
- キャンバスは `pointer-events: none`・`aria-hidden`。スイッチの入力と読み上げには何も足さない。

### 6.1 返す技術負債

| 負債 | どう返したか（2026-09-28） |
|---|---|
| おいわいの作りが遊びごとにばらばら（リールの星は Font Awesome を DOM に12個、ふうせんの紙吹雪は CSS の小片8枚、ボールの花火は CSS の星3つ、けっかのメダルは静止） | `fx` のプリセットへ集めた。古い DOM・CSS の粒（`.slot-cheer-star`・`.balloon-burst`・`.bb-firework` とその keyframes）は消した |
| はじめの遊び3つが、同じ「押す→音→進み→5回目→おいわい→けっか」を別々のタイマーで書いている | `beginnerKit.js` の `createBeginnerFlow` へ寄せた。3つの遊びから、読み上げ・終わり・記録のタイマーが消えた |
| けっかの画面は描き直すたびにアニメーションが最初からやり直しになる | 「見せ始め」を1回だけにした（gameHost の `revealPending`） |
| 動きの時間・曲線が CSS のあちこちに直に書いてある | 新しい動きは `fxMotion.js` の `MOTION` に集めた。既存の CSS の動きは、画面ごとに書き直すときに寄せる（今回は触らない） |
| 演出の強さの設定が無く、「びっくりする音」の注意書きだけが安全の手段だった | 強さの段階と上限をエンジンで持ち、設定「見え方・音」に「演出の強さ」を足した（§4） |
| 演出の強さは測定の条件になりうるのに、どこにも残らない | `session.config.fxLevel` → sanitize → CSV（リズム・リール・アーム・さかなつり・回の一覧）の3経路に通した |

返さない（今回は触らない）もの: `styles.css`（7600行）と `theme-hakkiri.css` の二重の層。
見た目の全面置き換えは、利用者の世界を1枚の新しいスタイルに書き直すときに、画面ごとに行う。

### 6.2 画面に収める規則

どの遊びも、字や絵が画面の外に出ず、上の帯（のこり・この遊びの設定・おわる）の裏に
入らず、スクロールが要らない。これを画面の大きさごとに確かめる（`tests/web-smoke.mjs`）。

- れんしゅうの回は、画面いっぱいに大きく（リールはコンテナの単位で1コマを決める）。
- そくていの回は、決まった大きさのままで収まる画面では何も変えない。収まらない画面でだけ、
  決まった大きさより小さく収める（大きくはしない）。実際に出した大きさは記録に残す
  （リールの `reelCellPx`）。
- 遊びの面の中身を上下の真ん中に置くときは、入りきらない分が上へはみ出して戻せなく
  なる。背の低い画面では、上の帯の下から詰めて置く。

## 7. 画面ごとの動き

| 画面 | 動き |
|---|---|
| スタート | 「はじめる」がゆっくり呼吸する（すでにある）。押すと、押した場所からきらきらが広がり、ホームへ |
| ホーム | 枠が来たタイルは少し持ち上がる（影が深くなる）。選ぶと、タイルが弾んでから遊びへ |
| おすと でてくる | 真っ暗な画面に、押すと輪が広がり、動物が弾んで出る。きらきらが回ごとに増え、色も増える |
| ふうせん わり | 割れた瞬間に、ふうせんの色の紙吹雪と「パン」の輪。残りのふうせんがびくっと揺れる |
| ぬりえ | 色がつく場所からしぶき。最後は背景の丸が広がり、虹色のきらきら |
| ボールを 打つ | 打った瞬間に火花。ホームランはヒットストップ → 花火 → 寄り。ボールに光の尾 |
| リール（れんしゅう） | 画面いっぱいのリール（どの画面でもはみ出さずにいちばん大きく。横長では目標を左へ）。「ぴったり！」で星がはじけ、続けて当てるほど星が増え、音が上がり、「2かい れんぞく！」 |
| アーム（れんしゅう） | つかんだ瞬間にきらきら、受け口に落ちたら紙吹雪 |
| さかなつり（れんしゅう） | 釣れた瞬間に水しぶきと、大きさの数字（「25センチ！」） |
| 高い音だけ（れんしゅう） | 合ったら音符がはじける |
| けっか | 星が1つずつ飛び込む → 一言のハンコ → 数え上げ → 2つ以上なら紙吹雪 |

## 8. 確かめ方

（2026-09-28 に確かめたこと）

- 単体テスト（`tests/fx.test.mjs`）: 強さの読み替え、端末の「動きを減らす」を見ないこと、そくていの回で none、
  揺れ・光の上限、1秒に3回の光の制限（どの1秒の窓でも超えない）、エスカレーションの単調増加、
  粒が減速して落ちて寿命で消える、全方向に片寄らずはじける、紙吹雪が画面の上から降る
- 記録: `fxLevel` が config → sanitize → CSV（台帳・反応CSV）を通る（`tests/data-integrity.test.mjs`）
- まとめ直した流れ（`tests/beginner-flow.test.mjs`）: 5回で終わり6回目を数えない、押した回だけ記録、
  フィナーレは1回、けっかは待ってから1回、連打では残りの声が最後の1回だけ、押す音が上がっていく、
  途中でやめたら声を止め・できたあとは「やったー」を最後まで読ませる
- けっかの画面の組み立ては `src/lib/games/results.js` へ分けた（`gameHost.js` 1036行 → 約600行。中身は移しただけ）
- 画面（`tests/web-smoke.mjs` の「adds effects within the safety rules…」）: キャンバスは
  pointer-events: none・aria-hidden・fixed、粒の最中でも次のひと押しが届く、動きが止まると
  描くのをやめる、けっかの星が飛び込む、強さ「なし」で粒が出ない、そくていの回で何も出ず
  `fxLevel: "none"` と記録される
- 重さ: フィナーレの最中のコマの間隔（Chromium、2倍密度、ソフト描画）。通常の速さで 60fps のまま。
  CPU を4倍遅くして中央値 16.7ms（60fps）、95% 点 50ms。演出なしは 16.7ms
- 目: 各場面をコマ送りで撮って見た（`test-results/fx-frames*.mjs`）

- 単体テスト: 強さの係数、明るい光の回数制限、粒の物理（重力で落ちる・寿命で消える・上限を超えない）
- 画面（Playwright）: 各遊びで演出が出てキャンバスに描かれること、入力をさえぎらないこと、
  強さ「なし」で粒が出ないこと、端末の「動きを減らす」でも雰囲気どおりに出ること、そくていの回で何も出ないこと
- 重さ: フィナーレの最中のコマの間隔（CPU を 4 倍遅くした状態で 30fps 以上）
- 目: 各場面をコマ送りで撮って、動きの流れを見る
