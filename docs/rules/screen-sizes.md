# 画面の大きさ

このアプリは iPad が中心で、iPhone・PC でも使う。展示会では PC の大きな画面にも映す。どの大きさでも、
字や絵が画面の外に出ず、上の帯（のこり・この遊びの設定・おわる）の裏に入らず、スクロールが要らないこと
（`docs/rules/ud-checklist.md` の A7）。

## 確かめる 14 の大きさ

| 大きさ（CSS px） | 何の画面か |
|---|---|
| 1133×744 ／ 744×1133 | iPad mini（横／縦） |
| 1180×820 ／ 820×1180 | iPad Air・10.9 インチ（横／縦）。**いちばんよく使う** |
| 1194×834 ／ 834×1194 | iPad Pro 11 インチ（横／縦） |
| 1366×1024 ／ 1024×1366 | iPad Pro 12.9 インチ（横／縦） |
| 590×820 | iPad の Split View（半分） |
| 1366×650 | PC のブラウザ（低い窓） |
| 1920×1080 | 展示会の大きな画面 |
| 844×390 | iPhone 横 |
| 667×375 | 小さい iPhone（SE）横 |
| 390×844 | iPhone 縦 |

どの検査がどの大きさを見るか:

| 検査 | 大きさ |
|---|---|
| `tests/web-smoke.mjs`（全部の画面の動き） | 1280×900（chromium）、iPhone 14＝390×664（WebKit）、834×1194、390×812、844×390 |
| `tests/responsive-screens.mjs`（説明とけっかの収まり。web-smoke から呼ぶ） | 667×375、844×390、390×844、834×1194、1180×820、1366×650、1920×1080 |
| `scripts/compare-measure-screens.mjs`（そくていの回が1画素も変わらないか） | 14 全部（`--quick` で 5） |
| `scripts/capture-screens.mjs`（目で見る材料。CI が撮る） | 5（`--all` で 14） |

## 収め方の決まり

- **れんしゅうの回**は画面いっぱいに大きく描く（リールはコンテナの単位で1コマの大きさを決める。`src/lib/games/slotFit.js`）。
- **そくていの回**は、決まった大きさのまま収まる画面では何も変えない。収まらない画面でだけ、決まった大きさより
  小さく収める（大きくはしない）。実際に出した大きさは記録に残す（リールの `reelCellPx`）。
  → `docs/rules/measurement-invariance.md`
- 遊びの面の中身を上下の真ん中に置くと、入りきらない分が上へはみ出して戻せなくなる。背の低い画面では、上の帯の
  下から詰めて置く。
- 幅で切り替える規則（`max-width`）だけでは、スマホの横（幅はあるが背が低い）に何も効かない。背の低さは
  `max-height` か `orientation: landscape` で別に見る（`src/responsive.css`）。
- 遊ぶ前の説明は、手順が全部入る画面では全部、入らない画面では1つずつ出し、前後のボタンで行き来する
  （`src/lib/games/readyScreen.js` の fit）。けっかは操作のボタンの場所を先に取り、中身だけを縮める。
- 走査で選べるものは、どの大きさでも入力ドックの裏に隠れない（ホームは 740px を境にページに分ける。
  `src/lib/scanPaging.js`）。
- タップの的は 44×44px 以上。
