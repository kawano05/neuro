# 全部の遊びで使う、4段階の雰囲気（2026-09-30）

`partyStage.js` を「出来事と主役を渡す舞台」にした。遊び別の舞台を増やすと、安全の上限・中断時の片づけ・研究の記録との境界が遊びごとにずれるため、ホストが1つだけ舞台を作る。`party.js` の `ATMOSPHERES` が段の文法と設定文のキーを持ち、`atmosphereProfile(level, kind)` が「はじめ」「タイミング」の上限を決める。

## 4段階

| 要素 | なし | すっきり | にぎやか（既定） | おおさわぎ |
|---|---|---|---|---|
| 押した手応え | 絵の変化と小さな弾みを残す | 残す | これまでどおり | 残す |
| 起きたことの粒 | なし | 数を減らし、大きさも60% | これまでどおり | 多い粒と輪・星 |
| 世界の動き | 止める | 止める | 動く | 動く |
| ラッコ | なし | なし | けっかだけ、拍手 | 最中も。課題では結果のあとだけ |
| キラキラびん | なし | なし | けっかだけ | 最中にたまる |
| 観客・旗・音楽 | なし | なし | なし | はじめの遊びだけ |
| フィナーレ | なし | 小さな星の輪 | 紙吹雪 | 紙吹雪・パレード・花火 |
| できたときの音 | 短いチャイムと声 | チャイム・短い拍手・声 | これまでどおり | ファンファーレを加える |
| けっか | 遊びの一言・評価と静止した星 | 同じ一言・評価に小さく星が入る | 同じ一言・評価にラッコとその回のびんを添える | 同じ一言・評価にびん・服・その日のびんを添える（押すと出てくるは従来の版面） |
| 服 | なし | なし | なし | 遊び終えたら1つ |

声・効果音のON/OFFは既存の別設定に従う。`resolveFxLevel` と既定値は変えていない。「動きを減らす」は normal/big を subtle にし、測定は none にする。測定には舞台も雰囲気属性も足さない。

## 遊びの入口

- 押すと 出てくる・ふうせん・ぬりえは `createBeginnerFlow` が `ctx.party.react({ index, source, name })` を呼ぶ。最後の1回は同じ入口でフィナーレを始める。押すと 出てくるの配置・動物の声・音楽の段・演出時刻は維持する。
- 野球は打球を主役として同じ入口へ渡す。投げる音（`playThrow`）が到着の手がかりなので、投げている間だけ音楽を下げる。打つ音とボールの動きは元の処理が持つ。
- リールは止まったリール、アームは景品、さかなつりは魚／長靴、高い音だけは判定位置を渡す。`success`、予定回数 `total`、`endless` も渡す。結果が確定する前に舞台へ通知しない。
- ホストが、遊びの終了処理・研究の保存が終わったあとにだけ、共通フィナーレとけっかへの移動を持つ。測定の終了時刻と待ち時間は変えていない。

## 配置と安全

課題のラッコとびんは小さく、瞬き・呼吸を止める。主役・遊ぶ面・札と重ならない150×100pxの角があるときだけ出す。幅900px未満や高さ400px未満では最中に出さず、けっかへ回す。課題の反応は220ms、節目のベルは80ms、ハンコは200msにとどめる。失敗は180msの小さなうなずきだけで、星を取り上げない。

はじめの遊びでは角の仲間を小さくし、押すと 出てくるは元の配置を使う。横向きスマホのけっかは作品とびんを横に並べる。測定のけっかにはこの圧縮を適用しない。

実入力の3回目も目視し、追加の3遊びでは観客を右端の列、旗を上の帯のすぐ下、はんぶん／いっぱいの札を左下へ移した。ふうせんの右端や、ぬりえの絵・投球の言葉に飾りを重ねないため。押すと 出てくるの配置には適用しない。

光・花火の上限は既存の `createBrightLimiter` を通す。新しい絵は既存SVGを使い、新しいPNGはない。課題では音楽・観客・旗を出さない。画面を切り替えるときには前の粒・舞台のタイマー・音楽を片づける。

## びん・服と研究の記録

はじめの遊びは1→3→7→11→15個。課題は成功した数を予定回数で割り、全部成功なら15個になる。No-Goの正しい見送りも成功として数える。エンドレスは成功1回で星1個、15個ごとに次のびんへ進む。

空のびんは0個のまま表示し、「いっぱい」と言わない。部分的にたまったびんを、その日の「いっぱいにしたびん」に数えない。服は成功数によらず最後まで遊んだことでもらう。全種類を持っている場合、部分的なびんには既存の「やったー！」を使う。

舞台の `summary()` はホストの表示用コピーにだけ `party` として付ける。ゲームが保存した `session.summary` は変更しない。保存・sanitize・CSV列・`session.config`の意味と既定値はそのまま。保存の `state.party` も同じ形を使う。

## 設定担当へ渡す文

設定画面は変更していない。`ATMOSPHERES[level].label` と `.description` を `t` / `tHtml` で解決する。

| 段 | 一言の説明 |
|---|---|
| なし | 絵と 押した 手応え。最後は 一言と 星。 |
| すっきり | 小さな 粒と 星の 輪。世界の 動きは 止める。 |
| にぎやか | いつもの 遊び。けっかで ラッコと キラキラびんが お迎え。 |
| おおさわぎ | 押したあとに 星が たまる。最後は パレードと 服の ごほうび。 |

4表記（ふりがな・漢字・かな・英語）を辞書に入れた。新しい声の文は0件。既存の `party.voice.*` と、既に声のパックに分割して入っている `party.praise.*`・「やったー！」を使う。声のパックを作り直す文はない。

## 検証の道具

- `npm run test:unit`：段の文法、予定回数の違い、空のびん、エンドレスの次のびん、服と日付、既存の研究データ契約を検査する。
- `tests/web-smoke.mjs`：従来の実入力・完走・中断に加え、ふうせん・ぬりえ・野球のbig完走と服・15個の星、3回目の観客・旗・札の非重複を検査する。高い音だけでは実際に高音を見逃し、低音を見送り、成功数だけ星がたまることと、合図前の仲間の静止を検査する。
- `node tests/party-visual.mjs`：製品のJSに検査用入口を残さない。はじめの4遊びは5回の実入力で完走する。課題側はテストビルドの共通入口へ確定後の出来事を渡す演出用の治具。12遊び方×4段×3実寸＝144ケース、各4段階＝576枚。配置・待機中の静止・けっかのボタン・横幅・服・研究summaryへの混入を検査する。課題の画像は成功演出の比較であり、実際の判定・保存・終了はweb-smokeと単体テストで別に検査する。

画像は `test-results/party-matrix/`、目視用の一覧は `test-results/party-review/`。変更前後の測定画面は `test-results/party-before/` と `test-results/party-after/`、RGB差は `test-results/party-pixel-diff.json`。細かな実行結果はこのワークツリーの `test-results/party-*.log` に残す。

## 初回の実行結果

- `npm run test:unit`：全スクリプト成功。雰囲気と片づけの決まりは11件、研究データ整合性は41件とも成功。
- `npm run build`：成功。
- 関連web-smoke：Chromium 1280×900で16件、WebKit 844×390で12件、合計28件成功。WebKitではWeb Audio内部の検査など4件を既存のブラウザー条件でスキップ。全42検査×5実寸の全体実行ではない。
- 撮影・配置：1180×820、834×1194、844×390で144ケース／576枚。36枚の比較一覧を目視。主役と仲間の非重複、課題の待機中の静止、結果のボタンと横幅を検査した。最初の目視で見つけたスマホ横の結果画面の重なりとボタンのはみ出しを修正した。
- 変更前後のRGB比較：測定6課題×iPad横／スマホ横の12枚が差0。押すと 出てくるのbigも、開始・1回目の押した直後×2実寸の4枚が差0。時刻・乱数・アニメーション・キャンバスをそろえ、アームでは画像のdecode完了も待って描画の揺れを分離した。全動作時刻や全フレームの同一性を示す比較ではない。

実行ログは `party-unit.log`、`party-build.log`、`party-smoke-final-pass.log`。結果の描き直しでも曲を止め、次の遊びの曲を止めない片づけを単体テストに加え、partyの実操作も両ブラウザーで追加確認した。追加実行は4件成功、デスクトップ専用の2件はWebKitでスキップ（`party-smoke-cleanup.log`）。撮影の最終記録は `party-matrix/checks.json`。画像名は `{実寸}-{段}-{遊び}-{during|pressed|finale|result}.png`。実入力の3回目は `party-live/{chromium-desktop|phone-landscape}-{balloon|coloring|baseball}-third.png`。

迷った点は、課題の合図を優先して決めた。余白が無ければ最中の仲間を隠す。正しい見送りにも星を与える。部分的なびんを「いっぱい」と数えず、服は最後まで遊んだことに与える。課題のnone/subtleの終わりには短いチャイムと既存の「やったー！」を使い、normalの最中の音・見え方は保つ。新しい声の文・声のパックを作り直す文はともに0件。

変更は `design/party-all` にまとめ、pushしない。検証サーバーは停止済み。

## 差し戻し1回目：一言と星の評価を主役に戻す

にぎやか・おおさわぎの描画が通常の評価を置き換え、課題の一言と3つ星を消していた。`renderPraise` と完了型の描画を全段で共有し、共通のお祝いはそのHTMLの下へ添える。5回中5回なら「すごい！ きみは プロだ！」と3つ星、成績が違えば従来どおりの一言・星になる。はじめの遊びは「できた！ 楽しかったね」と完了の星。押すと出てくるのおおさわぎだけは従来の版面を使う。

仲間とびんは小さく下に置き、スマホ横では評価の横に並べる。通常の星・作品の表示アニメーションも共有し、二重に動かさない。単体テストで0/5・3/5・5/5の一言と評価が全段で一致すること、完了型の一言・星と従来のポップの例外を検査する。撮影テストにも一言・評価・お祝いとの非重複の検査を足した。

再検証は `npm run test:unit` 全スクリプト成功（partyは13件）、`npm run build` 成功。関連web-smokeはChromium／WebKitで23件成功・3件スキップ、アイコンの縦伸びを直した後のWebKit実操作も1件成功。ログは `test-results/party-r1-{unit,build,smoke,smoke-final}.log`。

`node tests/party-visual.mjs` で全144ケース・576枚を再撮影し、指定のcrane・slot-l2・fishing・balloonについて4段×3実寸のけっか48枚を目視した。評価とお祝いは重ならず、スマホ横でも両ボタンが画面内に収まる。比較一覧は `test-results/party-r1-review/{ipad-landscape|ipad-portrait|phone-landscape}-{crane|slot-l2|fishing|balloon}.png`。従来の `party-review/` も更新済み。最終検査記録は `party-matrix/checks.json`、再撮影ログは `party-r1-visual.log` と `party-r1-visual-final.log`。押すと出てくるのおおさわぎは既存の描画・配置・演出を維持し、新しい声の文は0件。
