# 研究に必要なデータ（2026-08-29 時点）

卒業研究として何を主張するために、何を持っている必要があるか。
いまのアプリが出すもの・出さないものを、実物を確認して対応づけた。

「アプリが記録している」と「解析に使える形で出てくる」は別物なので、
最後の1列（どこから出るか）を必ず見ること。保存されているだけの値は、
実質「記録していない」のと同じ。

---

## 0. 前提となる研究の形

対象は重度肢体不自由でスイッチ操作を行う利用者。参加者は多くて数名で、
群間比較の統計的検出力は最初から見込めない。したがって研究の形は

- **単一事例／少数事例の記述**（参加者ごとに、何がどれだけできたか）
- **参加者内の比較**（訓練前後、条件間）

になる。この形では「事例の記述そのものが結果」なので、成績の数値より
**その回がどんな条件だったか**の記録のほうが重い。条件が言えない回は、
数値が取れていても使えない。

---

## 1. 試行レベルの一次データ（必須）

課題ごとに1試行1行。これが無ければ何も始まらない。

| 課題 | 主要な測度 | 出どころ |
|---|---|---|
| リズム（sms） | 拍とのずれ `rawOffsetMs`、判定 | リズムCSV |
| Go/No-Go | 押してはいけない拍で押した数 `commission` | リズムCSV |
| リール（slot） | 停止のずれ `signedErrorMs` / `absoluteErrorMs` | リールCSV |
| クレーン（scan） | 目標との距離 `distance`、判定 | 走査CSV |
| さかなつり（rt） | 反応時間 `reactionTimeMs`、判定 | 反応CSV |

いずれもBOM付きUTF-8。時刻は端末のローカル時刻（オフセット付き）。

---

## 2. 測定条件（必須。ここが欠けると数値が使えない）

同じ課題でも条件が違えば別のものを測っている。**混ぜてよいかを決めるのは
解析側**なので、アプリは条件を残すところまでを担う。

| 条件 | 何が変わるか | 出どころ |
|---|---|---|
| `difficultyMode` | そくてい（protocol固定）か、れんしゅう（支援者が調整）か | 全CSV |
| `measurementReadiness` | 課題が成立していることを確かめてから測ったか（met / overridden / n/a） | 全CSV |
| `visualGuidance` | 画面から拍の手がかりを出したか。ONの回は聴覚同期ではない | リズムCSV |
| `audioGuidance` | 目標の通過音を鳴らしたか。ONの回は視覚課題として成立しない | 走査CSV |
| `endless` | 難度が回の途中で上がる遊び方だったか | 走査・反応CSV、台帳 |
| 試行ごとの `sweepMs` | その試行が要求した時間精度（grip圏の半径 × sweepMs/100） | 走査CSV |
| 端末（画面実寸・DPR・音の出力遅延・UA） | 視距離・刺激の実寸・音の出方が変わる | 全CSV |
| `appliedBaselineMs` | 音の遅延補正をどれだけ当てたか | リズムCSV |

### 2026-08-29 に埋めたもの

いずれも「記録していない」または「記録しているのに出していない」状態だった。

| 追加した列 | どこに出るか |
|---|---|
| `deviceInputMethod`（direct / ios-switch-control） | 全CSV・台帳 |
| `limitMs`（試行ごとの受付時間） | 反応CSV |
| `sweepMs`（試行ごとのアームの速さ） | 走査CSV |
| `endReason`（planned / failure / cap / manual） | 走査・反応CSV・台帳 |
| `endlessProtocolVersion`（傾斜の版） | 走査・反応CSV・台帳 |
| `legacyVersion`（いまの版で検証していない回か） | 台帳 |

入力手段は `device` に置いた（全課題で共通の1か所）。押印は保存を通る
`persistSession` で、`endedAtIso` と同じ理由。

値を持たない古い記録はすべて空欄にする。「記録していない」と「既定だった」は
違う——空欄でないと、後から入れた列の既定値が、当時そうだったかのように読める。

---

## 3. セッション台帳（必須）

`neuronode-sessions-*.csv`。1セッション1行。

ロング形式のCSVは1試行1行なので、**試行が0件で終わった回はどのCSVにも
現れない**（中断、音が出せなかった回）。欠測を数えられないデータは、欠測が
無いデータと区別がつかない。台帳は次を持つ。

- 参加者ID、課題、開始・終了時刻（端末のローカル時刻）
- 完走か中断か、試行数、除外した試行数
- そくてい／れんしゅう、成立確認、エンドレスか
- 端末、`configJson`、`summaryJson`

**実施順もここから復元できる**（`startedAtLocal`）。順序効果を後から検定するには
これが要る。

---

## 4. 生データの控え（必須）

`neuronode-raw-*.json`。CSVは列を選んだ派生物で、選ばなかったものは出ない。
正本はその端末の localStorage だけにあり、端末を初期化すれば消える。
再解析・監査のために、書き出した時点でアプリが持っていたものをそのまま残す。

**操作ログまで含めて残るのはこの控えだけ。** 提出物には必ず含める。

---

## 5. アプリの外で取るもの（別紙）

アプリは記録しない。紙で取って解析時に突き合わせる。

- **参加者の属性**: 年齢、診断、運動機能、視覚・聴覚の状態、コミュニケーション手段
- **使用スイッチと設置**: 機種、押す部位、設置位置、姿勢、支持
- **実施環境**: 場所、同席者、時間帯、その日の体調・覚醒
- **条件の割付**: どの順で何をやったか、カウンターバランスの方法
- **主観評定**: 努力・やりやすさ・没入（単一評価者の3件法。信頼性の検討は
  できないので、限界として明記する）
- **観察メモ**: 数値に出ない出来事（中断の理由、介助の有無、機器のトラブル）

突き合わせの鍵は**時刻**。台帳の `startedAtLocal` / `endedAtLocal` と、別紙の記録
時刻を合わせる。参加者IDだけに頼らない（打ち間違い・切り替え忘れが起きる）。

---

## 6. 量の見積もり

そくてい（protocol固定）1回あたりの試行数と長さ。

| 課題 | 1回の試行数 | 1回の長さ |
|---|---|---|
| rhythm-l1 | 10 | 約20秒 |
| rhythm-l2 | 20 | 約24秒 |
| gonogo | 20 | 約28秒 |
| slot-l1 | 8 | 約26秒 |
| slot-l2 | 12 | 約38秒 |
| crane | 5 | 約28秒 |
| fishing | 12（期待値） | 60秒 |

来所4回とすると、1参加者あたり rhythm-l2 は80試行、**crane は20試行**。
crane は1回5試行と薄く、外れ値1つで平均が動く。個人内の変化を論じるなら
回数を増やすか、指標を成功数ではなく距離の分布で見る。

### 端末が保持できる量（重要な制約）

- `MAX_SESSIONS = 50`（全課題の合計、古い順に消える）
- 1回の来所で4課題を回すと **12回の来所で上限**
- 3人で端末を共用すると **1人あたり来所4回ぶんしか残らない**

→ **参加者ひとりぶんが終わったら、書き出して端末を空にする**運用が前提。
「参加者を切り替える」ボタンがこれを担う（書き出す前は消させない）。

---

## 7. 提出物（1参加者ぶん）

1. `neuronode-sessions-YYYY-MM-DD.csv` … 台帳（何回やったか、欠測を含む）
2. 課題別CSV（実施した課題ぶん）… リズム／リール／走査／反応
3. `neuronode-raw-YYYY-MM-DD.json` … 生データの控え（操作ログを含む）
4. 別紙 … 属性・スイッチ・環境・割付・主観評定・観察メモ

`neuronode-log-*.csv`（操作ログCSV）は「いつ何を押したか」であって、試行
レベルのデータは1件も入っていない。**これだけでは提出物にならない。**

---

## 8. 残っている穴と、埋めるなら何をするか

すべて 2026-08-29 に対応済み。

| 穴 | 影響 | 対応 |
|---|---|---|
（なし）

対応済みのもの:

- 入力手段の記録（`deviceInputMethod`）
- 試行ごとの `limitMs` / `sweepMs` をCSVへ
- エンドレスの終了理由（`endReason`）と傾斜の版（`endlessProtocolVersion`）
- 推移と自己最高を participantId で絞る（共用端末で別人の記録が混ざっていた）
- 通常のさかなつりが推移に出るようにする（条件キーから実現試行数を外した）
- リールの版を上げても既存データを消さない（`legacyVersion` で識別して保持）
- 書き出しファイル名の日付も端末のローカル時刻から作る
