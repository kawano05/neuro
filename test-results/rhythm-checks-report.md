# リズム検査の更新報告（2026-10-01）

作業ブランチ: `design/rhythm-checks`。変更対象は `tests/web-smoke.mjs` とこの報告書。`src/`、保存形式、sanitize、CSV、測定プロトコルは変更していない。push は行わない。

## 指示書と実装の差

旧 `rhythm-l1` / `rhythm-l2` はホームに出ないだけでなく、`src/lib/games/registry.js` の `gameModules` にも登録されていない。`findGameModule(id)` が null になり、`gameHost.launch(id)` は何もせず戻る。さらに旧2種の説明も `gameHowTo` から外れている。したがって指示書の「ホストへの直接 launch で旧2種を開ける」という前提は成立しない。

これは README の旧課題の履歴互換方針と整合するため、旧課題をテスト用に再登録せず、実際に利用者が開ける `gonogo` を使った。`gonogo` と `calibration` は旧課題と同じ `games/rhythm.js` の入力・判定・記録・中断処理を通る。全検査を登録し、生オフセットの等式、5入力すべての hit、入力差への追随、予告要素の不生成、静止計器盤、既存の短い画面の寸法検査を残した。

## 3検査の変更とassertの置き換え

### checkRhythmRecordsRealOffsets

- 古い `version: 3` の seed をやめ、現行アプリの保存を `patchSettings` で更新する。基準60msは維持。
- 「リズム→リズム練習」をホームの「高い音だけ」へ置き換える。8拍（Go 5拍・No-Go 3拍）を最後まで通す。
- `exposePresentationContext` は配信JS応答だけで実コンテキストを公開する。Service Workerをこの検査だけ遮断し、応答注入がキャッシュで迂回されないようにする。
- 実スケジューラの `start` を呼んで音の計画・時刻対応を観測する。判定、入力受付、記録は差し替えず、5つのGoに物理クリックを送る。No-Goのランダムな配置とホスト側時計の誤差に依存した時刻計算を解消する。
- `finishReady` で現行の説明画面を抜ける。全拍の `finished` 保存を待ってから、最後の判定が結果遷移まで読める時間残ることを検査する。

| 前 | 後 | 理由 |
|---|---|---|
| 完了した `rhythm-l1` セッションがある | 完了した `gonogo` セッションがあり、taskType・8拍・8試行・No-Goの正しい見送り3件も一致 | 旧課題は起動不能。実際の聴覚課題で共通エンジンの完走と記録の欠落を検査する |
| `abs(rawOffsetMs) <= effectiveWindowMs` | `abs(rawOffsetMs - appliedBaselineMs) <= effectiveWindowMs` | 判定窓の中心は基準Cだけ移動する。生値を中心0の窓で検査するのは設計に合わない |

生値が有限、`rawOffsetMs = inputMs - scheduledMs`（許容1ms）、各hitの基準60ms、5入力すべてhit、入力間の差に120ms以内で追随、値の幅100ms超、最終フィードバックの維持は削除・緩和していない。

### checkRhythmVisualProfiles

現行の `gonogo` をホームタイルから、`calibration` を支援者の設定→研究→`#startCalibration` から開く。新規練習の既定値、予告あり練習lane、予告なし練習instrument、測定instrument、基準をとる回instrumentを検査する。測定・基準の未来ノートは「隠れている」ではなくDOM要素0件を要求する。

| 前 | 後 | 理由 |
|---|---|---|
| 旧2種＋gonogo＋calibrationのテーマID4種 | 現行gonogoとcalibrationのテーマID2種、各モードのprofile・themeを個別照合 | 旧2種は登録表からも外れた。現行の全聴覚課題と版面を固定する |
| `<i>` のclassが4種 | アイコンの実markupが3種で、すべて非空。練習はSVG1件、測定・基準はSVG0件 | gonogo練習に音楽会のSVGが入り、測定の盾・基準の時計と区別する必要がある |
| 背景画像が4種 | 練習・測定・基準の背景画像が3種。音楽会の風景は練習だけ1件、測定・基準は0件 | 予告あり／なし練習は同じ絵。研究の回に練習の絵が漏れないことも追加検査 |
| 狭幅・短画面でconsoleの3枚すべて可視 | 3要素は存在し、練習のprofile-panelだけdisplay:noneかつ幅0。得点・目盛りは可視、目盛り幅86px以上、切れ・重なりなし | `theme-hakkiri.css` が練習の冗長な版面ラベルを意図して隠すため |
| `.module-color` の旧プリズム・進行欄・HUDを検査 | `.module-pop` の `.pop-stage`・`.pop-dots`・`#gameSettings` を同じ寸法・非重複条件で検査 | 「押すと 出てくる」は説明なしで始まる動物の舞台へ変更済み |

844×390、390×812、507×812、619×390、568×320、422×195の既存の検査寸法と許容2pxを維持する。レイアウト失敗は再現画像を保存し、残りの版面・測定のassertまで続けたうえで最後に必ず失敗を投げ直す。失敗をskip扱いにはしない。

### checkRhythmL1GameFlow

関数名は既存名を維持し、検査一覧の表示名はgonogoに合わせた。ホームで走査が動く状態から「高い音だけ」を選び、説明を `finishReady` で終える。遊び中に走査停止・枠0件・支援者chrome非表示を検査し、Escでホームへ直接戻す。

| 前 | 後 | 理由 |
|---|---|---|
| `rhythm-l1` の `aborted:true` が保存される | `gonogo` / `taskType:gonogo` / `aborted:true` / `finished:false` が保存される | `rhythm.js.destroy()` はgonogoにも共通の中断確定処理。ホームにある遊びで利用者の実導線を検査する |

音APIのないブラウザでは利用不能の理由表示・Escでホーム・保存セッション0件を実際にassertしてokとする。音が必要な上の2検査は従来どおりChromium以外をSKIPPEDとする。
